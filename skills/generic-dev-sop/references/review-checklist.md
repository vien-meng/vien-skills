# 代码审查清单

交付/合并前逐项核对；不满足的项必须修复或标记为阻塞，不能静默略过。技术栈绑定规则以项目级 coding-rules skill 为准。

## 范围与设计

- [ ] 只实现已确认范围，无范围漂移、无顺手重构。
- [ ] 方案与开发记录、验收条件一致；非目标未被破坏。
- [ ] 无只在对话中描述、未写入记录的决策。

## 结构与复用

- [ ] 无重复代码，优先复用既有组件/工具/依赖。
- [ ] 无空泛抽象、预建接口或单一实现的多余 interface。
- [ ] 无超长组件（>400 行）或深层嵌套（>6 层）未拆分。
- [ ] 长常量表、类型与工具函数未堆在组件文件里。

## 类型与校验

- [ ] 无不必要的 `any`，无非空断言 `!` 覆盖。
- [ ] 外部输入已在 DTO/校验层验证，业务代码信任校验结果。
- [ ] 类型/编译检查通过。

## 错误处理与数据安全

- [ ] 用户可见错误统一格式 + 稳定错误码，不泄露堆栈/密钥/内部路径。
- [ ] 写接口归属校验未放宽，权限边界安全。
- [ ] 无数据丢失风险：回滚/取消/幂等/迁移已考虑。
- [ ] 密钥与令牌只存环境变量/安全存储，日志已脱敏。

## 状态与并发

- [ ] 单一状态源，无组件私有业务状态；派生数据未在 render 中修正。
- [ ] 异步流程覆盖 pending、error、cancel/retry。
- [ ] 并发、竞态与幂等正确（重复提交、离线重放、服务重启场景）。

## 可访问性与多语言

- [ ] 用户可见文案走多语言资源，默认语言 key 对齐。
- [ ] UI 覆盖键盘、读屏、焦点、对比度与触摸目标。

## 平台边界

- [ ] 平台能力用运行时适配器判断，无构建分叉。
- [ ] 共享层无平台 SDK 依赖，平台类型未泄露。

## 测试与证据

- [ ] 非平凡逻辑留有最小可运行检查。
- [ ] 执行的命令、结果、人工检查点与已知缺口已记录。
- [ ] 失败项已修复或标记为阻塞。

## 规范一致性

- [ ] 声明注释、命名、路径别名符合 `references/coding-standards.md`。
- [ ] 组件私有样式与组件同目录同名，无远程借用私有样式。
