# 通用编码规范

语言无关的核心规范；技术栈绑定规则（如 React/MobX、NestJS 模块、Flutter 分层）以项目级 coding-rules skill 为准，本文件不重复。

## 声明与注释

- 所有导出声明（`interface`、`type`、`class`、`function`、`const`、`enum`、模块）在声明正上方写清晰的多行 `/** ... */` 中文注释，说明用途；涉及单位、取值边界、异常、副作用、持久化或平台差异时必须一并说明。
- 单行 `/** 说明。 */`、普通 `//` 注释或只复述声明名称都不满足要求；内部声明与导出声明执行同一标准。
- `enum`/`const` 的每个成员、`interface`/`type` 的每个属性、DTO 的每个字段逐项注释，确保 IDE 悬停即可读懂。
- 注释写 WHY（隐藏约束、微妙不变量、绕过的具体 bug），不写 WHAT（好的命名已表达）。

## 命名

- 描述性词汇；类与类型帕斯卡命名，变量与函数小驼峰，单行常量与常量数组全大写蛇形。
- 布尔类型属性/方法使用 `is`/`has` 前缀；不使用内置 getter/setter，用 `getVal()`/`setVal()`。
- 尽量不用前置/后置下划线；未使用参数用 `_` 前缀规避 lint。

## 类型与空安全

- 尽量不使用 `any`；仅在外部边界（第三方全局变量、用户输入）明确放宽。
- 不用非空断言 `!` 覆盖，用 `if` 判断替代；空值路径显式处理，不让空值静默穿透。

## 导入与路径

- 跨模块引用统一使用配置的路径别名；相对路径只用于同目录或同一模块内部，禁止新增 `../../../` 一类跨层级导入。
- 路径别名必须在 TypeScript、构建、测试与实际运行环境全部解析一致；Node/Electron 运行时代码不得依赖 TypeScript 不改写的裸别名。
- 无未使用导入，import 顺序与命名按项目 lint 规则。

## 数据结构与持久化

- 稳定 ID 使用 UUID；时间统一 ISO 8601 UTC 或整数毫秒/微秒，禁止浮点秒累计漂移。
- 持久化模型只放可序列化数据；禁止写入运行时句柄、DOM/平台对象、本地绝对路径、临时 URL 或可变缓存。
- 迁移、回滚与兼容策略先于实现；字段来源、默认值与校验写入开发记录。

## 错误处理与安全

- 外部输入先在 DTO/校验层完成校验，再进入业务代码。
- 用户可见错误统一格式 + 稳定错误码；响应不得泄露堆栈、密钥或内部路径。
- 所有写接口执行归属校验：普通用户只能操作自己的资源，`admin` 按 RBAC 例外处理。
- 密钥与令牌只存在于环境变量或系统安全存储，禁止写入代码、测试或仓库；日志脱敏。
- 不使用 `eval`；所有用户内容输出做转义，防止注入与 XSS。

## 状态管理（有状态框架适用）

- 单一状态源：业务状态由状态层（Store）管理，组件只渲染状态输出并转发事件，不持有私有业务状态。
- 派生数据用 computed/派生字段，不在 render 中修正数据；批量或异步更新走明确 action。
- 异步流程覆盖 pending、error、cancel/retry；外部输入先校验再进入状态层。

## 组件与结构（UI 框架适用）

- 单个组件文件目标不超过 400 行，JSX/DOM 嵌套不超过 6 层；超过时拆成单一职责子组件并由父组件组合。
- 组件私有样式与组件文件同目录同名；禁止远程引用其他组件或布局的私有样式，公共样式集中管理。
- 列表、禁用态、可见性与文案状态来自状态层，不在 JSX 内筛选、排序或拼接业务数据。
- 列表 `key` 使用稳定 ID，不使用数组索引。

## 平台差异

- 用运行时适配器判断平台能力，禁止用 `VITE_PLATFORM` 一类构建分叉替代运行时判断。
- 共享层只依赖稳定领域接口；平台 SDK 只在适配层调用，不把平台类型泄露进共享代码。

## 依赖与抽象

- 复用既有组件、工具与依赖；新增依赖必须在开发记录说明必要性。
- 单一实现不建 interface，至少两个模块真实复用才抽象；不预建 repository/factory/微服务等空泛层。
- 有意的简化在代码处用 `ponytail:` 注释说明天花板与升级路径（如全局锁、O(n²) 扫描）。
